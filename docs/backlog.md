## 待修问题

### P1

1. **覆盖率统计有盲区。** vitest 只统计被测试导入过的文件，约 48 个源文件从未计入（其中 37 个 `.tsx`、约 8200 行，包括 `AgentTeamsScreen`、`TeamDesignerCard`、`use-design-save`）。行 90% / 函数 85% 的门槛只证明被导入文件覆盖良好。建议先用 `coverage.include` / `exclude` 明确统计范围，再分阶段补组件级测试，不要直接打开 `coverage.all` 导致门禁突然失败。
2. **"采用预设"后，带未知扩展字段的 Role 下次同步显示为"本地修改"。** 原因是 `appliedHash` 取自预设候选行，而当前行的 hash 计入了保留下来的扩展字段。默认动作是"保留"，不丢数据。正确修法：采用时按"候选 + 原行扩展字段"重新计算 `appliedHash`（客户端与服务端都要改）。不要改成"只比较预设管理的字段"，那样会把用户手加的扩展字段当作未改动，下次同步可能丢失。
3. **协调者 Profile 无法解析时，只显示为普通启动阻断。** 设计师和启动预览都缺少"去选 Profile / 去绑定"的引导。
4. **宿主行为：`plugin remove` 会清空整个插件设置目录。** 之后打开 Team 页会对空目录自动导入默认 Role。需要在 README 写明：升级请用版本面板或原地 reload，不要先 remove 再重装。

### P2

5. **turn-ended hook 早于账本初始化到达时会被丢弃。** 要等下一次设计 RPC 才会补对账（可恢复）。建议 hook 路径也做幂等的初始化重试。
6. **"创建结果不明"仍靠匹配错误文本判断**（`uncertainCreate`）。应在 adapter 层把 SDK 错误映射为稳定的错误类型。
7. **G6 补测试。** 变异测试显示 `roleWrittenByJob`、补偿的 `leaseOwner` 拒绝、"取消后校验失败仍保持 canceled"这三处删掉后没有测试能发现。建议补一条"Role 已不在账本里 → `DESIGN_NOT_SAVED`"用例。另外，写入 Role 后崩溃、没调 `saveFailed` 就被取消时，Role 会残留（不误删）。
8. **turn-ended hook 每次都读一次账本文件；日志原样写出底层错误信息。** 建议加缓存，日志脱敏。
9. **既有代码仍透传 `Error.message`。** 位于 `use-designer-workspaces`、`LaunchDialog` 等处，应改为固定文案或结构化格式。
10. **未在 DEV 上实测的路径：**
    - 版本管理确认框"无法列出提交"一支。缺对象时整次检查会先报网络失败，难以单独制造。
    - `/team-design` 斜杠命令。workspace 的 Claude 标签页没有渲染输入框，只从代码确认了它只做预填。
11. **版本 DTO 的兼容范围。** 响应现在会忽略未知字段，但新增枚举值或升级 `schemaVersion` 时，仍须先发布能识别新值的客户端（`shared/version.ts` 顶部有注释）。本版之前的旧 App 读到新 daemon 返回的 `pendingCommits` 会失败。
12. **设计师默认 Profile 顺序为 Opus-5.5-Max → Astra-Max → Opus-5.5-High → Gemini-4-Argon，费用高。** 可考虑在设计卡片上提示费用，或默认改为"自动选择"。本轮 DEV 验收用 Claude Haiku 4.5 完成了设计，用满 3 轮，约 136 秒。
