行为要点：

- **每 5 秒轮询一次本地 RPC**，Run 到达终态后停止；不涉及模型调用。
- **按钮由 `waiting().options` 决定**，界面不自己判断什么状态能做什么。放弃、已合并、接受当前提交这三类不可逆操作需要点两次确认。
- **审查者的权限模式在界面上就拒绝**：选了不在允许列表里的 Profile，"启动"变灰，并写出原因（和 Spec 7.2.3 同一份判断函数，服务端仍然会再查一遍）。
- **工作区面板**：在 `team/<runId>/…` 的工作区里直接显示这个 Run 的详情，在别的工作区里显示列表。
- **Profile 来源**：宿主配置里的 `agentProfiles`（SDK 的 `config.get()` 把配置文件里 `daemon.agentProfiles` 展平到了顶层）。

## 3 测试中发现并修掉的问题

1. **0.15.4 的工作区快照没有 `branch` 字段。** 面板原来靠它认出 Run，结果在 Run 自己的工作区里也只显示列表。改为从工作区的 `name` 和 `directory`（`team-<runId>-writer`）里取，主机改显示名时目录名仍然稳定。类型检查对着 0.15.4 的 SDK 时也会报这一处。
2. **窄屏下新建对话框崩溃（`ThemeProvider is missing`）。** 宿主在窄屏把 Modal 渲染成底部抽屉，不在我的组件树里，React context 传不过去。改为在 Modal 内部再包一层主题提供者。宽屏时没有这个问题，所以只有换宽度测才发现。
3. **`useTheme()` 写在提前 `return` 之后**（lint 抓到）：数据到达时 hooks 数量会变，React 会报错。挪到其他 hooks 旁边。
4. **`draftProblems` 把一个字符串当数组展开**，每个字符变成一条提示。单元测试抓到。
5. **PR 的 CI 失败**：见第 6 节。

## 4 为了守住 900 行预算而砍掉的范围

按 Spec 第 4 节的规则，界面写不下就削减界面范围，不挪用服务端额度：

- **没有"展开日志""打开报告"。** 客户端读不到 worktree 里的文件，要做就得加服务端 RPC。现在显示完整路径（文字可选中复制）。
- **没有"复制路径"按钮、没有 `paseo-team.json` 的加载提示。** 默认值仍然会从该文件读入对话框。
- **新建对话框不记住上次选的 Profile**，也没有宿主级默认值的设置界面（`teamSettings` 在服务端已注册，界面没有接）。
- **列表不显示总耗时**，只显示轮次、验收次数和多久前有进展。
- **没有"侦察兵""重新验证（基线变了）"**，这是 P1。

## 5 没有验证的

- 通过界面启动 Codex `full-access` 审查者。服务端路径在 M1b 验证过，界面这一段没有重复。
- 通过界面添加多个审查者并真实运行；打回后的第二轮。
- "有权限请求在等"和"基线已前进"这两条提示：代码在，DEV 里没有构造出这两种状态。
- 触摸操作和真正的移动端 App，只测了 420 像素宽的 Web。
- 长时间打开页面时的轮询行为；多个 Run 同时活动。

## 6 PR #42 的 CI 失败

PR 开出后 CI 失败：`@getpaseo/plugin/server` 没有导出 `defineAgentTool`。原因是 CI 按锁文件安装的开发依赖是 `0.13.0-beta.1`，而我本地的 `node_modules` 里早先装过 0.16 的类型，所以本地的 `tsc` 一直是过的。

- 已把 `@getpaseo/plugin`、`@getpaseo/client`、`@getpaseo/protocol` 的开发依赖固定到 `0.15.4`（v2 要求的宿主版本），`@getpaseo/cli` 不动，单独一个提交。
- 对着 0.15.4 的类型，v1 和 v2 的 `tsc` 都没有新错误；M1c 里用到 0.15.4 没有的 `branch` 字段，是这次才被类型检查抓出来的。
- 教训：本地类型检查要和 CI 用同一套依赖，改完依赖后在干净的 `npm ci` 环境里再跑一遍。

## 7 顺带看到的

- **空提交可以通过门禁。** "求助测试"里写手拿到回答后没有改任何文件就调用了 `team_submit`，门禁命令是 `true`，通过了，进入审查。门禁只看命令的退出码。这是服务端行为，不是界面问题；是否要求"相对基线必须有改动"见 Spec 第 18 节。
- DEV 宿主的 Agent Profile 要写在 `config.json` 的 `daemon.agentProfiles` 下。写在根上会让 daemon 拒绝启动（`Unrecognized key`），已写进 `AGENTS.md`。
