## 难度等级（建议）

- **L1 机械**：批量改写、文案、格式化、简单脚本。
- **L2 常规**：规格清晰的单模块功能、补测试、原因明确的缺陷修复。
- **L3 复杂**：跨文件或跨层的新功能、新 RPC 或 DTO、UI 接线、需要做设计取舍的修改。
- **L4 关键**：状态机、并发与崩溃恢复、持久化与数据安全、git 和版本更新、安全边界、跨模块合同与架构。
- **判定信号**：
  - 涉及以下任一项，至少定为 L3：持久化写入、并发、崩溃恢复、外部副作用（创建 agent、git、发布）、合同变更；
  - 同时涉及两项以上，或者没有现成模式可参照，定为 L4。

## 分配规则（建议）

| 难度 | 实现 | 审查 | 验收 |
| --- | --- | --- | --- |
| L4 | S 层实现；或 A 层实现、S 层审查 | A 层（Opus-High）审查，并要求真实 store / 真实环境用例 | DEV 实测 |
| L3 | A 层（Sol Max / Sonnet） | A 层（Cursor-Sonnet） | DEV 冒烟 |
| L2 | B 层（DeepSeek） | A 层（Cursor-Sonnet） | 按需 |
| L1 | B 层（DeepSeek / Grok-4.6） | 抽查 | 无 |

- 决策和架构始终由 S 层完成，包括需求定稿、方案、跨模块合同、合入结论。
- **升级**：同一任务在当前层返工 2 轮后仍有阻断，升一层（B → A → S）。
- **会话轮换**：经济执行者大约 4 个长回合后换新会话。

## 插件需要实现的能力（交需求分析师细化验收标准）

1. **Profile 能力层级**：S / A / B / 禁用，作为 host 级设置。按 hint 匹配预填默认值，默认值参考上表；用户可以修改。层级内的 Profile 不可用时，要有回退规则。
2. **任务难度等级**：L1–L4。
   - 协调者派活前先定级；
   - roster 中标注每个成员的层级，以及能承接的难度；
   - 按规则挑选成员，或请求创建对应层级的执行者；
   - 升级与回退规则写进协调者提示，并记入运行记录。
3. **与 5A 的组合**：模式（SOTA / 经济 / 协作）、Role 分层（decision / execution / escalation / retain）、难度等级三者如何组合，需要统一设计，不能形成两套互相冲突的规则。经济模式下，执行层要按难度从池里选 Profile。按需创建与扩容属于 5B 的范围，要评估是否一并做、做到哪一步。
4. **Team 设计师**：设计时为每个成员标注承接的难度，按层级选 Profile，并在结果卡上展示。
5. **可观测性**：运行记录中记下每个任务的难度、所用模型和返工次数，供后续调优。
6. **兼容**：旧 Team / Role 没有层级信息时，行为保持不变，沿用 SOTA 兼容规则。
